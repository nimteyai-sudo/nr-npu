# NR-NPU

Нейроморфный движок для RK3588 NPU — запускает спайковые нейронные сети (SNN) через обычные 2D-свёртки на NPU.

## Идея

NPU не умеет в спайки. Но спайк — это просто вектор, где `i`-й элемент = 1.0 если нейрон `i` сработал. Такой вектор можно подать как тензор в Conv2D, и NPU выполнит матричное умножение (синаптические веса). Весь цикл LIF (накопление, утечка, порог, сброс) делает CPU.

```
Вход → Кодирование спайков (CPU) → Conv2D (NPU) → LIF-обновление (CPU)
         ↑                                                      ↓
         └──────────── индексы спайков ─────────────────────────┘
                        (повторить T раз)
```

## Результаты

Модель: 784→128→10 (MNIST), INT8 квантование

| T (таймстепы) | Точность | Задержка | Энергия |
|---|---|---|---|
| 3 | 98.0% | 2.2 мс | 0.036 Дж |
| **5** | **99.0%** | **3.9 мс** | **0.051 Дж** |
| 10 | 99.0% | 8.9 мс | 0.085 Дж |
| 20 | 99.0% | 18.1 мс | 0.146 Дж |

ANN baseline на том же железе: 96.7%. SNN даёт выше точность при меньшей задержке (при T≤10).

Оптимальная конфигурация: **T=5, threshold=1.0, leak=0.1 → 99%, 3.9мс, 0.051 Дж**

## Запуск

Требования: Orange Pi 5 Ultra (или другая RK3588 плата), Python 3.11, RKNN Toolkit Lite 2.3.2.

```bash
pip install numpy  # rknn-toolkit-lite2 должен быть установлен заранее

# Демо с визуализацией спайков в терминале
python3 demo.py -n 20 -t 5

# Бенчмарки (T sweep, INT8 LIF, throughput)
python3 tools/test_phase2.py

# Измерение энергопотребления
python3 tools/measure_energy.py
```

Предобученные модели лежат в `models/`. Тренировать ничего не нужно.

## Что внутри

**Кодирование спайков.** Каждый спайк = плотный тензор `(1, C, 1, 1)`, где `C[i]=1.0` если нейрон `i` сработал. Каналы выравниваются до кратных 8 для NC1HWC2.

**LIF нейрон.** Два варианта: float32 (стандартный) и int16 (целочисленная мембрана с вычитающей утечкой). Дают одинаковую точность, float чуть быстрее — NPU всё равно де-квантует в float32.

**Конвертация ANN→SNN.** Linear слои становятся Conv2d(1×1) с выравниванием каналов. Веса те же, порог LIF подбирается по максимальному весу слоя.

## Находки

1. **T=5 хватает для 99% на MNIST** — в 4× быстрее чем T=20
2. **RKNN сериализует вызовы inference** — мульти-поток на разных ядрах даёт 0.16× (медленнее!). Конвейерная обработка невозможна в одном процессе.
3. **Выравнивание каналов по 8** — модели нужно проектировать с каналами кратными 8 с самого начала, паддинг не работает (проверено эмпирически)
4. **INT8 квантование без потери точности** для этой архитектуры
5. **Холодный старт NPU** — первые 1-9 инференсов медленнее (прогрев кэша)

## Ограничения

- RKNN `batch_size>1` падает (segfault)
- Нет мульти-ядерного конвейера в одном процессе
- CPU-side LIF ≈ 0.05мс/шаг (ничтожно против диспетчеризации NPU)
- 2 слоя; каждый дополнительный слой = +1 диспетчеризация NPU
